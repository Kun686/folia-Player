# 本地歌单与收藏

2026-10-12，本次移植补齐本地歌单的新建、重命名、删除、添加／移除歌曲、上下移动、收藏与队列保存。
播放使用歌单当前显示的顺序；移除成员或删除歌单不会删除音频。混合队列保存时明确提示本地歌曲数量，
在线歌曲仍由原平台管理，不保存临时播放地址。

## 复用与存储

- 原 `localPlaylistService` 的规范化、旧格式兼容、去重、收藏初始化、重复导入身份和删除引用修复，
  提取到 `localPlaylistModel`、`localPlaylistIdentity` 和可注入存储的 `localPlaylistStore`。
  桌面端保留原导出接口与 `local_playlists` 缓存位置；移动端复用同一业务实现。
- 使用已安装的 Dexie，独立数据库 `FoliaMobileLibrary`、版本 1、`lists` 表中的 `library` 记录。
  与可清理缓存分开；只保存名称、时间、收藏标记及原生 mediaId，不复制音频或保存本地绝对路径。
- 临时 `LocalSong` 投影复用原名称规则与分组，原生目录和匹配记录仍是歌曲数据源。
  不把这些投影写入桌面曲库，不把同名文件自行合并。
- 每次操作使用独立 IndexedDB 读写事务。先完成一次读取以取得写锁，再读取原生目录，
  用 Dexie 的有界 `waitFor` 保持事务（10 秒）；读取、引用修复和修改一起成功或回滚。
  两个连接并发修改与延迟目录读取有专项测试。原生文件删除与 IndexedDB 不是跨存储原子事务：
  删除成功后下一次完整目录刷新清理引用；失败会保留歌单，下次刷新可恢复一致。
- 歌单专用目录读取要求完整：UUID 目录缺少／损坏 `song.json` 或 sourceRef 身份不匹配时拒绝读取，
  防止部分结果触发破坏性清理。普通浏览继续展示可读歌曲。未知存储版本和写入错误也不会覆盖原记录。
- 写入失败显示错误并保留输入；单次提交防重复。界面恢复前台时重新加载，以最新成功读取为准。

没有新增生产依赖。播放器全屏布局、透明控制器、在线平台规则与音频播放实现保持原行为。
