# 收藏专辑与音乐云盘移植

## 实现与复用

移动曲库新增 QQ／网易云「收藏专辑」及网易云「音乐云盘」。原有歌单、全屏播放器、歌词动画与控制器样式保留。
没有新增依赖、原生接口或存储格式。QQ 不显示原 provider 未提供的云盘能力。

- 收藏专辑复用 Library Core 的 `createHomeFeedResource`、`loadAllFavoriteAlbums`，每页 50 张，按原顺序读完；
  用已有 `react-window` 列表展示，进入专辑后仍使用原目录资源与原生播放／队列接口。
- 增加 Omni 的 `getProviderUserAlbums`，移动端显式按账号来源路由，不改变桌面 active provider；原 `getUserAlbums` 保持兼容。
- 网易云云盘元数据经 `getProviderCloudCollection` 读取，曲目复用现有 `catalogSession` 的 50 首分页、重试与退出清理。
  保留 `sourceRef.providerId/mediaId/variant: cloud`，不把云盘歌曲伪装为本地文件；播放解析仍复用原规则。
- 页面关闭、平台／账号变更会使旧资源失效，不再翻后续页或提交晚到结果；失败保留已成功读取的数据。
  收藏专辑刷新按原资源从首页重读，云盘曲目续页失败从失败 offset 重试。
- 收藏专辑和云盘的失败／缺失列表不再被 provider 当成成功空列表。真实空数组仍显示为空；诊断不打印上游正文、地址或会话。
- 原生凭据仍在 Keychain，经现有网络桥请求；新入口没有 localStorage 凭据或新的平台登录实现。

本批提供账号曲库读取与播放入口；专辑收藏／取消收藏等写入动作尚未接入移动端，不把本批记为完整账号库能力。

## 网关与回退

新增认证后的只读路由：网易云 `/album/sublist`、`/user/cloud`，QQ `/user/albums`。
继续使用固定内部地址、禁止重定向／自定代理、禁止转发网关认证头；分页沿用目录范围检查（limit 1–1000，offset 0–10000）。
`/mobile/health` 可选公布 `userAlbumProviders`（QQ／网易云）与 `cloudProviders`（网易云）；仅公布已启用平台。
旧网关缺字段时禁用相应入口并提示更新；专辑入口还要求现有专辑浏览能力，避免列表可读但无法打开。

部署锁定网易云 API 4.40.1 的两个模块与本机 4.41.1 逐字一致；QQ 路由和 controller 核对已安装及部署锁定的 3.1.4。
源码摘要见 `upstream-source.json`，这只证明调用依据，不证明实际账号权限、远端内容或可播放性。
后续先更新网关，再安装匹配 App；回退网关和前端资源即可，无数据迁移。

本轮没有部署服务器、请求真实账号库或安装／重启个人 mobile.28。
