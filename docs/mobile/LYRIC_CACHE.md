# 移动端完整歌词与来源选择持久存储

2026-10-11，接续 [COVERS.md](COVERS.md) 和 [ONLINE_LYRICS.md](ONLINE_LYRICS.md)。本阶段补齐前台
与原生播放共用的在线歌词存储。个人安装包仍为 0.7.16 / mobile.10；独立 QA 包用于真机测试，
本阶段的源码和测试不能表述为个人安装包已经更新，也不代表完整移植已经完成。

## 复用与实现

- 前台重新接回原 `loadOnlineSongLyrics`，保留 Omni 路由、自动匹配、导入选择和纯音乐判断。
  只增加可注入存储接口；Web／Electron 默认仍用原资源键、IndexedDB、旧缓存迁移和导出元数据。
- 原歌词选择函数提取成纯模块，让 JavaScriptCore 与前台共用；没有在 Swift 重写歌词格式或选择规则。
  验证继续使用原 `.fia` 文档解析器，保留逐字、翻译、罗马音、注音、背景人声、手工分词和渲染提示。
- 原在线 JavaScriptCore 协议增加可选 `full` 输出，默认规划输出不变。QQ QRC、网易云 LRC／YRC
  的完整结果与原前台解析器对照；原生规划仍只投影它所需的行时间和文本。
- Swift `NativeLyricCache` 按 provider、sourceRef 和来源 variant 存储，复用 `NativeProfileIdentity`。
  文件为 `Application Support/FoliaLyrics/<provider>/<identity hash>.json`，原子写入，首次解锁后可读。
  不保存原始接口响应、Cookie、网关凭据或播放签名 URL。
- 每份歌词文档最多 2 MB，每条记录最多 8 MB；保留原规划器 2000 行及时间范围限制。普通在线记录
  使用 64 MiB LRU；导入及已确认的覆盖选择属于已保存的数据，不随自动淘汰删除。这类记录计入
  设置显示的实际占用，因此总量可以超过 64 MiB。用户主动清除或退出对应平台会删除它们。
- 复用封面的文件清单、大小统计和清理代码为 `NativeResourceFiles`，封面目录及行为不变。
  Foundation、JavaScriptCore 和现有依赖已经足够，本阶段没有新增依赖。

## 状态、并发与失败

原生及前台优先读取已存歌词。启用自动匹配时，先显示缓存再刷新；网络刷新失败保留缓存显示。
纯音乐的已确认空歌词是有效结果，不反复请求。原生后台读取同一份已保存选择，缓存缺失才经既有
接口取得歌词；其运行不需要 WebView。磁盘写入失败时仍可使用本次内存里的歌词时间，歌词服务失败
沿原无歌词规划继续，不中止音频。

平台级随机写令牌在清除／退出时失效，前台额外检查账户和清理代次。原生验证结束后才合并最新记录，
迟到的基础歌词不会覆盖已经保存的选择。账户 Cookie／token／userid 更换会清理对应平台歌词并重新规划；
队列切换、取消或退出后，过期结果不能发布。活动中的音频过渡继续使用已经固定的时间表。

设置沿用原 `lyrics` 分类，与音频、封面占用及清理分开。清除前明确提示会删除在线歌词和来源选择；
本地音乐导入目录中的歌词保留。清理失败显示错误。当前屏幕持有的歌词可继续显示，不要求重新解码当前歌曲。
本阶段建立来源选择持久化能力，在线歌曲的完整手工歌词编辑／来源管理界面仍待移植。

独立 QA 宿主及测试插件的 Bundle ID、签名 team、宿主 entitlement、xctestrun SHA256 已核对，见
`lyrics-cache-device-identity.json`；真机仅运行经核对的 `test-without-building` 配置。
测试结束已卸载 QA App、关闭本轮模拟器，设备回读个人包仍为 0.7.16 / build 10，见

早期逻辑测试错误地把原 LRC 最后时间推断为 10 秒，现改为与原解析结果对照，未改变解析算法；

## 回退

回退本阶段提交可恢复原前台歌词入口和仅内存的原生规划。新增目录使用独立版本格式，旧代码不读取；
保留目录可供重新升级恢复，删除会丢失已保存的在线来源选择，不能把它当成无损回退步骤。
根 README、依赖锁、音乐 API 规则与服务器配置均未修改。本地播放和动效继续不依赖网关。
