# 原版可选同步服务移植

2026-10-12。开发源码新增「服务器与外观 → 同步服务」，复用原版 Hono sync-server 协议、歌曲指纹、Merkle 分桶、主题注册表、视觉设置快照和 ZIP 格式。没有新增依赖，没有部署服务，也没有更新个人 mobile.28。

## 行为与范围

- 默认关闭；未配置或安全存储读取失败不影响播放器启动。音乐网关、AI 服务和同步服务分别配置。
- 保存 HTTPS 地址、启用状态与写入式同步凭据；空输入保留旧凭据，明确勾选才清除。更换地址（包括路径）清除旧凭据，可以同时提交新凭据；失败保留草稿。
- 测试连接同时检查原版 `/health` 与受认证 `/state`；启用后复用原启动主题同步与手动主题同步。只有主动点击“同步视觉设置”才下载并应用较新的远端外观，再上传当前快照。
- 同步下载后刷新当前歌曲缓存，保留既有自定义主题优先级及全屏播放器布局。保存单曲后的即时自动上传、缺失单曲的即时远程查找尚未接到移动主题 hook；当前使用启动／手动整库同步，不宣称已实现全部原版同步触发路径。
- ZIP 导出通过已有原生 ZIP 分享通道；导入先选择文件、校验内容并确认，随后只恢复本地。需要上传时再手动同步；界面明确说明此区别。关闭同步也能导入／导出本地备份。
- 延续桌面命令入口 `settings-r2-sync`、`sync-now`；移动端通过触摸设置页操作，没有另建命令体系。原视觉快照和导入导出 schema 保持不变。

## 凭据、并发与存储

- 凭据位于独立 Keychain `sync.settings`，JS 只读 enabled/baseURL/hasToken/scope/revision。移动运行时不读取旧 localStorage 同步凭据，也拒绝向那里保存凭据；ZIP 不含凭据。已有旧键不会被自动迁移或上传。
- 原生固定九种操作与路径；不接受 JS 提供 URL、Cookie 或 HTTP header。仅配置的服务器收到同步 Bearer token，不带音乐或 AI 凭据。
- HTTPS 地址禁止 userinfo/query/fragment、路径穿越、编码分隔符；所有重定向拒绝。独立 ephemeral URLSession 禁用共享 Cookie、HTTP 凭据及缓存。
- AI 与同步共用有界 URLSession 接收器和请求生命周期实现，但各自保留独立的请求所有者、凭据、并发槽和限额。同步最多两个请求，120 秒期限，请求 ≤2 MiB、单次响应 ≤8 MiB；AI 原 256 KiB/1 MiB 限额保持。
- 配置原子写入后递增 revision 并取消旧请求。JS 操作全程捕获同一连接，取消／换服务后不能把旧结果提交给新连接；旧配置回读不能覆盖新 revision。
- 同步状态、外观更新时间和主题水位按随机 scope 隔离；更换地址或凭据会生成新 scope。scope 本身不包含凭据。
- 原生 HTTP 错误只返回状态和空正文；前端保存固定错误提示，不记录远端错误正文或凭据。取消不撤销已经完成的远端上传，界面明确说明。
- 下载主题与指纹索引在同一 Dexie 事务中提交。与请求开始前的本地记录及缓存内容比较，期间发生的手动修改不会被下载结果覆盖；写入或连接检查失败会回滚整个事务。外观拉取也检查期间是否发生本地修改。
- 移动端每次拉一个分桶、列表每页 50 条；累计远端主题 JSON 限 16 MB，重复分页游标／超过 1000 页明确失败。过大的单桶或单次上传明确报错，没有截断结果或伪报完整同步。
- ZIP 压缩文件和展开内容均限 16 MB；导出 JSON 另设 15 MB 预留格式开销。导入复用已安装 fflate 的解压过滤器预检展开大小，不提取到文件系统。

## 剩余与回退

完整移植继续进行。仍需补齐单曲同步触发路径、独立原生页面触摸／键盘／旋转验证，以及真实服务和多设备一致性验收。对于超大主题库，本阶段采取明确限额，尚未实现单桶超限的分页降级。

本阶段基线为 `6000edb`。不改服务器版本；个人 App 无需回退。源码回退时保留 Keychain 和本地缓存，不卸载个人 App。`BUILD_RECORD.json` 继续只描述个人 mobile.28，不用 QA 构建覆盖它。
