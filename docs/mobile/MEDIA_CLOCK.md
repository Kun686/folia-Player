# 分轨接管的精确媒体时钟

2026-10-12，接续 [接管准备器](STEM_HANDOVER_PREPARATION.md)。
**PASS_DEVICE_CLOCK / FULL_AUTOMIX_IN_PROGRESS**。仅独立 QA，个人 App 保持 mobile.28。

## 原因与实现

分轨 PCM 必须与原解码器在同一个音频采样时刻对应同一段歌曲。
`NativeTempoStream` 的 TimePitch 进度是根据输入历史和初始延迟校正的估计，
既有测试允许速率变化期间约 40ms 的时间误差，不能把该进度包装成逐样本准确的分轨锚点。

本轮复用现有原始 PCM 游标、AVAudioSourceNode 时间戳和共享输出时钟，新增小型
`NativeMediaClock` 值与 render-owned tracker。没有新增依赖、计时线程、音频解码器或 DSP。

- `StreamRenderSource` 把真实宿主 sampleTime 传入 `NativeTempoHandover`。
  仅在 raw、1×、完整读到该块 PCM、尚未 EOF 时，将媒体末位置与宿主块末采样帧一起发布。
- 锚点包含 source UUID 与 epoch。暂停、欠载、seek、媒体跳变、宿主时间线重启、
  待执行的变速、错误或关闭均撤销旧锚点；新解码器具有不同 UUID。
- TimePitch 即使回到 1×，也不发布精确锚点。原有普通进度、歌词快照和变速输出保持原路径。
  分轨调用方必须处理锚点不可用，不能将估计位置冒充精确位置。
- 使用现有非阻塞发布锁；回调只处理标量状态，无新增分配、网络、模型或主线程等待。
  控制侧可立即清空发布值，由下一次渲染执行 epoch 重置，避免跨线程写渲染状态。
- `StreamMixOutput.mediaClock` 仅在引擎运行、锚点末帧与当前共享输出末帧**完全一致**时返回。
  落后一块也拒绝：旧快照可能掩盖一次尚未发布的欠载，不能直接向前外推当作当前证据。
  两路读数不一致时，调用方需要重新获取；最终调度还必须检查 source／epoch 和队列意图。

音频引擎暂停、启动及配置变化时先撤销发布值，所以恢复后、第一次新回调之前不会重新暴露旧锚点。
没有启用公开 `stems/full` 能力，也未连接 `NativeCrossfade.begin` 的四轨发声分支。

## 最终测试

证据目录 `.mobile-test-results/media-clock/`，最终源码与包清单为
`source-final.json`、`packages-final.json`；准确测试参数保存在 `test-*-final-command.json`。

| 环境 | 最终结果 |
|---|---|
| iPad Pro 11-inch M5 / iOS26.5 模拟器 | `simulator-final.xcresult`：35 通过、0 失败、0 跳过 |
| iPhone XS Max / iOS18.7.10 独立 QA | `device-final.xcresult`：35 通过、0 失败、0 跳过 |

覆盖原始 PCM 欠载／暂停／seek／EOF、原 TimePitch 波形与时间约束、共同输出、主音轨转场、
分轨调度和取消、精确锚点的失效与恢复。最终值已由 xcresult 摘要核对，没有用选中参数数量代替执行数量。
早期命令还选中了只在 `FOLIA_AUDIO_OUTPUT_PROBE` 下编译的旧 HTTP 探针，实际未执行；
最终过滤器已明确排除它，并纳入本轮真实输出用例。

新增双解码手动渲染用例验证 32 个共同块：两首歌起点差 0.75 秒、宿主末帧一致、
source 不同、恢复后 epoch 改变。另有**非手动渲染**用例实际启动系统输出，
收集 16 对时钟并暂停／恢复；两端最终的媒体位置差计算误差最大约 `1.11e-16` 秒，
采样率 44100。这是已知生成音频的两路时钟差计算结果，**不是扬声器端延迟测量或听感验收**。
样本是生成 WAV，没有 QQ／网易云访问、模型推理、歌词动画或长期后台播放。

首次构建后补齐了引擎重启失效；已有测试通过后又发现旧一块快照可能隐藏欠载，
收紧一致性条件并在最终两端完整复测。没有通过放宽时间精度或关闭保护得到通过。
上一阶段准备队列的首轮真机超时仍按原记录保留，本轮没有宣称已解决该资源问题。
