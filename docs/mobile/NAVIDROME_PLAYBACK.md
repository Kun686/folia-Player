# Navidrome 原生播放

2026-10-13。本批把已存在的 Navidrome 连接接到原生双声道播放引擎，沿用原队列、解码、ReplayGain、
拖动、网络恢复及可选媒体缓存。没有新依赖，没有修改播放器 UI、动画或音效算法。
**移动设置／浏览、封面与歌词仍未装配，尚不能作为完整移动音源交付。**

## 实现与复用

- 原生队列接受 `kind: navidrome`、原歌曲 `mediaId` 和 Keychain 连接 `scope`。
  Subsonic 的字符串 ID 以查询参数编码，不套用网易云／QQ 的字符限制。
  缓存沿用现有远程缓存分组；内部键包含完整 scoped 引用的摘要，三个原在线平台的键不变。
  这只是缓存归属，Navidrome 仍不进入 Omni 或音乐网关。
- `NativeNavidromeClient.audioSource` 在原生读取会话，调用原 `getSong` 路由检查账号及歌曲 ID、获取 ReplayGain，
  再用原 Subsonic 参数签名 `/rest/stream`。保持不传 `format` 的原默认行为，未添加转码规则。
  `getSong` 的 HTTP 200／Subsonic code 40 也按认证失败处理，不交给音频解码器猜测。
- 复用现有有界请求容器，浏览最多两项、当前／下一首解析独立最多两项；浏览不能占满播放名额。
  保存凭据成功后统一取消两组请求。失败的 Keychain 保存保留旧配置、队列及正在播放的声音。
- 缓存读取前、异步处理后和解码交付前均校验连接。禁用、更换服务器／账号／密码会停止并移除对应队列，
  清理其媒体／分析缓存及预加载；其他音源仍可播放。
  即使在 Keychain 提交与清理之间崩溃，重启恢复的旧队列也不能借用新会话或旧音频缓存。
- 认证、禁用或会话变更立即停止；普通失败沿用解析一次重试、连续三首失败停止的现有策略。
  更新 QQ／网易云音乐网关只停止属于该网关的当前歌曲，不把 Navidrome 当成网关音源。
- 队列、快照、媒体目录只保存歌曲身份和数值／显示元数据。丢弃传入的 Navidrome 流地址、签名封面地址与凭据字段。
  目前封面／歌词缓存仍只服务其已有音源，避免新身份误入尚未接入的 provider 请求路径。

签名 URL 仅在原生内存中使用。Subsonic 媒体拒绝全部 HTTP 重定向，包括同源跳转；配置应直接指向最终 HTTPS 入口。
原生媒体下载和分析前缀请求复用现有 delegate；AudioStreaming 1.4.5 增加一个默认开启的重定向开关，
只为原生签名 Subsonic 地址关闭。原在线 CDN 行为和解码算法保持原样。
固定上游 59 个文件、原始哈希、当前哈希和完整补丁均重新核验，见 `AUDIO_STREAMING_VENDOR.json`／`.patch`。

应用本身使用已接入的双声道流式引擎。保留的旧 AVPlayer 验证路径不接收 Navidrome，
防止绕过上述重定向限制；其本地及三个在线平台行为继续保留。

证据目录：`.mobile-test-results/navidrome-playback/`。网络响应和 WAV 音频为受控样本，解码／混音／输出为真实原生执行。

三曲测试测量实际 PCM，并自动播放完三首；断言无音乐网关解析调用、无 WebView 播放调用。
另覆盖拖动、快速切歌、断网重连、仅有本地缓存时的播放、保存失败保留声音、取消慢请求、其他音源继续播放、
浏览并发不影响播放，以及“新凭据＋旧持久化队列／缓存”的崩溃恢复场景。
认证错误只解析一次、停在第一首；503 连续失败的请求计数为 `[2, 2, 2, 0]`。
下载、分析和解码三条路径均验证重定向目标收到零次请求。

原生扩大回归的选择列表曾包含一个仅在 `FOLIA_AUDIO_OUTPUT_PROBE` 编译条件下存在的旧本机 HTTP 用例；
该用例没有被编入本次包，不计入通过数，交付复测列表中已移除。实际结果以 `.xcresult` 为准。
最后复核在 ReplayGain 异步计算之后补上取消／会话校验，避免已撤销的请求启动解码器；交付构建与同组原生复测单独留档。
