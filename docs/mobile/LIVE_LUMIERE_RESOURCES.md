# 真实歌曲绘光页面资源检查

2026-10-14。用户选择暂时只测已登录的 iPhone 模拟器，iPad 真实账号配置及验收暂缓。
沿用 [当前范围](CURRENT_SCOPE.md)：QQ／网易云核心、原版动画、设置 UI。

**结论：真实暂停歌曲的绘光页面完成8次展开／收起，歌词与控制器均恢复；
WebContent占用有明显回落，本场景未复现持续累积。不能据此宣称无泄漏、长期稳定或旧镜台问题已解决。**
本批没有修改生产代码、安装包、服务器或依赖；只补充有限采样和验收记录。

## 环境与方法

- iPhone 17 Pro，iOS Simulator 26.5，UDID `9213032A-657A-40CD-BD2A-A3065ACCC8EC`。
- 独立包 `app.folia.validation.App`，沿用 [动效设置对比度修复](VISUAL_SETTINGS_CONTRAST.md) 的已安装资源。
  128份资源与前批清单逐个匹配，相关4份源码摘要匹配；本批未重新构建。
- 已签名安装包可执行文件与前批已签名暂存副本一致：
  `8974f113a4abc0d3f5ea19be76a96ea0c1e4c685b97c04215c99ac0129738689`。
  内嵌版本仍为0.7.16／28，应以资源清单辨认候选；个人 iPhone 的 mobile.28 未更新。
- 使用已登录账号及原队列里的《爱爱爱》／方大同，保持暂停1:53，不注入歌曲或平台响应。
  模式为绘光（Lumiere），没有执行音频或PCM验收。
- 手动展开播放器，确认歌词实际渲染，收起并确认曲库后采样，共8轮。
  `PlayerPanel.tsx` 的 `rendering` 要求 `visible && expanded && !modalOpen`；收起后卸载 `MobileVisualizer`。
  这不是旧Diorama开关设置、连续PCM播放的同场景复测。
- 复用 `dev/mobile/sample-joint-processes.py` 的进程身份检查和系统 `footprint`。
  App／WebContent／GPU为10919／10926／10927，各阶段前后验证精确进程身份；
  最初通过可执行文件、父进程及指定模拟器环境元数据关联，未成功从WKWebView直接读取PID。
  不输出进程完整环境、凭据或平台Cookie。
- 每阶段3次有限采样，取各进程footprint中位数；没有强制GC、持有画布探针或无限日志。
  操作停留时间不固定，不作速率回归或性能阈值判定。阶段1与2之间镜像工具到时退出并重启，
  App和三进程未重启；镜像带来的系统负载影响未排除。

## 工具与操作偏差

- 准备时滚动面板仍在回弹，一次点击误打开官方歌曲页，随后返回；此导航不计入8轮。
  原生选项菜单操作曾选到心象，已明确改回绘光并截图确认，之后才建立轮次基线。
  最初计划选择镜台未成功，不能把绘光结果归到镜台。
- 两次只读LLDB诊断未取得WebView进程PID：一次表达式编译失败，修正后一次ObjC异常；
  均已detach，没有继续重试。改用上述系统元数据，保留关联方法的边界。
- 首次安装身份检查误将已重签名可执行文件与重签名前的 `nativeBaseSHA256` 比较，断言失败；
  改为已签名暂存副本后一次核对通过，128份资源与源码摘要也一致。
- 镜像辅助进程由600秒上限退出，已按指定UDID补做清理并关闭临时浏览器页。
  没有再次运行此前失败的memgraph或真实PCM测试，也没有触碰iPad连接设置。
