# 本地歌曲自动匹配移植

日期：2026-10-13；基线：354014971c6737de18918f50fdae096cbcba4827。
继续不依赖真机的工作；个人 mobile.28、服务器、真实账户和已确认的播放器布局未更新。

## 补齐的行为

移动端此前已有手动匹配，但原生播放本地歌曲没有自动匹配歌词、封面和歌曲信息。
现在原生当前／下一首歌词任务可执行原版自动流程，并通过已有事件刷新前台歌词和曲库。
本地音频始终直接播放；可用的文件歌词先交给播放协调器，搜索、会话或保存失败保留已有歌词。
只有原设置恢复完毕、现有音乐网关可用且原版自动匹配条件满足时才发起匹配。

- 从 localMusicService 提取同一份策略：最佳歌词、已选元数据身份、纯音乐、网易云 50 条搜索回退、
  标题匹配、文件歌词优先时仅补信息／封面，全部沿用原规则。桌面入口注入原 provider 元数据解析与 Omni 请求。
- 原生复用现有 JavaScriptCore 匹配任务、provider 协议和解析器，不在 Swift 重写歌曲匹配算法。
  网络任务只接收标题、艺术家、专辑、时长及选择状态，不携带本地音频、歌词文件或封面字节。
- 自动结果与歌词来源在同一记录原子保存，保留明确选定的文件歌词，保护 manual／manual-match／split 曲库归属。
  保存前后校验歌曲编辑令牌、曲库版本、任务取消和所有平台会话版本。
- 当前／下一首同时完成时，允许一次重新核对曲库版本；只有该歌曲完整快照未变化才重试保存。
  手动改歌词、编辑该歌曲的曲库归属、退出账号或取消任务后的迟到结果被丢弃。
- 更新队列中的信息，不更换正在播放的解码器，不重置进度；自动通知遵守已锁定的 Automix 计划。
  匹配歌词先发布，在线封面预缓存随后执行。

未增加依赖、模型或设置。匹配字典留在短生命周期任务，常驻解析器脚本从原 297,436 字节变为
301,919 字节；匹配脚本从 1,401,809 变为 1,406,412 字节，总增量 9,086 字节。
这是未压缩脚本体积，不能解释为 App 安装体积或内存增量。
