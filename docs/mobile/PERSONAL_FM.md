# 私人 FM 移植

## 行为与复用

网易云曲库提供原版私人 FM 和模式选择。沿用 `fmModes.ts` 的默认、熟悉、探索、拼图、场景及其完整场景目录，
沿用 `usePersonalFmModeStore` 的本地偏好；FM 播放期间切换模式立即请求新批次，成功后替换队列并从第一首播放。
尚未播放 FM 时只保存偏好，不中断用户主动选择的歌单。QQ 沿用原 provider 的能力，不伪造 FM。

原 `netease.ts` 的歌曲解析及 provider 的统一歌曲映射被原样提取到 `shared/mobile/neteaseSong.ts`，
客户端与 `/mobile/fm` 共同调用。`neteaseFm.ts` 共享原请求路径、模式参数及一次默认模式回退；
认证失效、限流、取消不会再进入回退，失败不记录原响应或凭据。
Swift 不复制音乐平台规则，只接收已有歌曲身份与标准字段。UI 调用原生播放接口，普通在线业务仍经过 Omni。

原生 `NativePersonalFM` 负责连续队列，在剩余约两首时预取下一批，WebView 挂起仍可请求。
请求沿用播放解析的短时后台执行保护，在完成、取消或到期后释放；它不是无限后台运行或真实锁屏验收的替代。
队尾等待期间暂停、退出 FM、退出账号或播放普通歌单会取消待执行提交；手动切歌／拖动会使迟到的模式切换失效。
模式切换失败保留旧歌曲和旧模式；补曲失败保留已有歌曲，到队尾停止，必须明确重试，不循环请求。
认证／限流会停止对应网易云播放，不中断其他平台歌曲。

FM 沿用原版连续推荐语义，不把普通循环模式应用到旧批次。队列最多 1000 首，达到上限时保留当前歌曲和此前 20 首，
再追加新批次；不按歌曲 ID 删除重复出现的推荐，保留歌曲出现顺序。清空队列退出 FM，保留当前已播放的独立歌曲。
“退出 FM，保留队列”停止补曲，剩余歌曲继续按普通队列播放。重启恢复身份和模式，但保持暂停，不自动发请求。

新增入口复用现有面板和主题，处理安全区、旋转、44px 选择控件；全屏播放器、歌词与动画未改。
无新增依赖、模型或数据迁移。旧网关或旧原生容器不支持时明确禁用入口。

## 服务与发布

网关认证后新增 `/mobile/fm`，仅允许网易云，必须提供该平台会话。只通过固定内部后端请求 `/personal_fm` 与
`/personal/fm/mode`，不允许自定地址、转发网关认证头或跟随重定向。响应大小、并发数和超时沿用现有网关限制。
`personalFmProviders` 为可选能力字段，限已启用的网易云。

核对部署锁定 API **4.40.1** 的两个模块，与本机 4.41.1 对应文件逐字相同；SHA-256 见本轮 `upstream-source.json`。
这证明路径和参数来源，不证明真实账户推荐内容或模式服务可用性。
Dockerfile 增加共享模式目录的复制；按镜像文件集合在 Node 24.17.0 实际加载网关成功，无需前端环境或额外依赖。

部署须先更新网关并核验认证／能力，再安装匹配 App；回退本批网关、原生包和 Web 资源即可。
旧 App 忽略新能力，新 App 遇到旧网关禁用 FM。旧 App 恢复队列时忽略 FM 字段，不自动继续补曲。
本轮未部署服务器，未安装或重启个人 mobile.28，未调用用户真实 FM 接口。
