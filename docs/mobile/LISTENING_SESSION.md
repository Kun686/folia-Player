# 网易云听歌打卡：原生计量与协议复用

2026-10-13，按用户要求继续不依赖真机的工作。当前阶段实现并验证独立原生计量模块，
尚未把它接入生产播放事件、后台发送、会话取消与设置开关，因此**移动端听歌打卡尚未交付**。
不发送真实账号记录，不更新个人 mobile.28 或服务器，不改变界面、动画、音效或已批准依赖。

## 原版复用

- `PlaybackListenTracker` 继续承担累计时长、30 秒门槛、2 秒最大进度步长、总时长上限、
  墙钟合理性和重复结算保护。增加显式 `discontinuity()`，拖动／暂停／输出变化后重新定位，
  连小于两秒的主动拖动也不计入。原 Web hook 的既有计量方式未改变。
- 把原歌曲资格判定提取为 `playbackListeningIdentity`，供 Web hook 和原生脚本共用。
  仍只接受网易云在线目录歌曲，排除云盘、其他平台和本地歌曲；额外拒绝不能用 JS 安全整数表示的 ID，
  防止数字舍入后向另一首歌写记录。保留桌面旧来源推断；原生输入必须显式携带 `sourceRef`。
- 把原网易云 provider 的音质映射、名称／歌手／秒数参数和响应判断提取到
  `shared/mobile/neteaseReport.ts`，原 adapter 调用此模块。四档音质、默认档、取整、缺少状态码时失败、
  登录错误语义不变，原注释随实现保留；不伪造歌单来源。普通前端调用继续经过 Omni。

`nativeListeningRuntime` 管理播放轮次，直接使用原 tracker。不同歌曲或同曲的新轮次结算上一轮，
同曲元数据／进度快照不会重开。暂停、异常位置及显式跳转切断连续采样；关闭或退出通过 `discard`
丢弃未上报时长。非有限或回退时钟丢弃会话，正常时间由原生单调时钟提供。
新轮次等音频真正开始播放才建立，避免缓冲阶段未知总时长被永久保留；未知时长仍按原逻辑允许不报 total。

`NativeListeningSession` 在私有 JavaScriptCore context 运行该脚本，限主线程，验证脚本协议和体积，
JSON 边界返回结构化的歌曲身份／实际计量时长。未重写一份 Swift 计时算法，也没有新增运行库。
脚本随现有移动构建生成，当前压缩文件为 **3,366 字节**；此数字不是 App 二进制增量。
