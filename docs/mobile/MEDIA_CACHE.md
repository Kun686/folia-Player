# 原版音频缓存移植

2026-10-11，个人开发候选 mobile.10。复用原音频设置 store、缓存控件、文案、容量选项、歌曲身份和分析器；
原生使用 Foundation 文件与下载 API，不新增依赖。安装状态以 BUILD_RECORD.json 为准。

## 行为

- 默认关闭；默认 5GB，0 表示不限量。淘汰最近最少播放的歌曲，缓存命中会更新使用时间。
- 自然播完或完成 Crossfade 后保存在线音频；手动跳过不保存。开启缓存时，原过渡分析可提前保存完整音频。
- 当前／待播优先读取已有缓存，即使之后关闭缓存开关。关闭开关取消待执行写入，已有文件可继续离线使用。
- 清理或容量淘汰取消写入并删除索引；已打开的播放引用继续持有文件直到解码器释放，拖动仍然可用。
  被占用的文件因此可能暂时使实际磁盘用量高于显示的可复用缓存大小。
- 退出对应平台会清除该平台的缓存、队列曲目与分析记录，不影响其他平台或本地导入。
- 目录为 App 的 Caches/FoliaMedia，系统也可能回收。清理不触碰 Application Support 中的导入音乐。
- 音频错误时移除失效缓存，再沿原有在线恢复路径处理；错误不会伪装为播放成功。

## 下载与分析

完整文件由 URLSessionDownloadTask 写入临时文件；接受 200 或覆盖全部文件的 206，验证完整长度与容量，
拒绝部分范围、文本／JSON 和压缩传输。请求只接受 HTTPS，重定向最多 5 次，每次重建请求，
不继承网关认证、平台 Cookie、URLCredentialStorage 或共享 URLCache。网络／磁盘错误只报告固定错误码。

相同歌曲身份与表示共用一个任务，完整下载串行执行，减少多首大文件竞争。清理、配置变化和退出取消拥有的任务；
任务代次检查保证迟到结果不能重新发布。临时播放 URL 不写入缓存索引；索引保存精简歌曲信息、文件代次和 LRU 时间。

完整缓存的分析以歌曲表示与文件代次为键，复用原 JavaScriptCore 分析，返回完整尾部信息；
未启用缓存且无完整文件时，继续使用原 1,572,864 字节前缀策略。相邻分析任务加入不会取消仍需要的当前歌曲任务。

## 验证与边界

原生测试位于 NativeTests/MediaCacheTests.swift、MediaCacheIntegrationTests.swift。
覆盖实际下载委托、容量／截断拒绝、取消、重定向、去重、串行、LRU、文件引用、恢复、账户清理、
自然 EOF／跳过、无网关缓存播放、清理后拖动、完整分析与 Crossfade 后离线重播。
13 项 iPhone XS Max / iOS18.7.10 专项通过，包括原在线前缀回归。完整证据索引见 VALIDATION.md。

界面使用原设置控件，移动逻辑测试 51 项；原 UI 24 项与新增缓存 UI 3 项通过。界面中的歌曲／响应为明确的测试样本。
真实平台、CDN、TLS、长时间锁屏、物理听感与温升没有因此获得 PASS。

本项移植的是音频缓存。封面与歌词属于原项目独立缓存类别，移动端持久缓存尚未接入；离线时可能无封面或歌词，
音频仍可播放。缓存没有新增“下载管理”功能，也没有改变原界面主题或原动画实现。

回退：保留 mobile.9 安装包；该版本忽略 FoliaMedia 目录。原媒体缓存关闭时保持原在线前缀策略；
恢复旧包需使用正常开发签名安装，缓存目录不是导入音乐的唯一副本。
