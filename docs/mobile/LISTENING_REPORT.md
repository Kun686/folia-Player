# 网易云听歌打卡：移动播放器接入

2026-10-13。继续不依赖真机的移植工作，源码基线 `2de0ccd5cafbca009838fa3bd4165a9de7aa5a4a`。
在上一阶段 [原生计量模块](LISTENING_SESSION.md) 上接通原生播放事件、后台请求、会话取消和原版默认关闭的设置。
这次没有新增依赖，没有更新个人 mobile.28 或服务器，也没有提交真实账号记录。

## 复用与行为

- `PlaybackListenTracker` 仍负责原 30 秒门槛、连续进度累计、总时长上限、墙钟合理性和幂等结算。
  显式拖动使用同一重播规则：已合格的一轮回到开头会结算；向前拖动不产生播放时长。
- 从原 `playbackReportGate` 提取共享 limiter：5 秒最小间隔、每小时最多 60 次、一个请求在途、15 秒截止。
  尝试在发送前计入额度，失败不重试；ticket 防止取消的旧回调释放较新的请求槽。桌面仍经 Omni 上报。
- 私有 JavaScriptCore 运行原计量与频控。`NativeListeningReporter` 管理元数据、播放轮次、请求和原生后台任务。
  生产播放器每 250ms 从真实音频输出供样，不依赖前端定时器；等待解码、暂停、拖动期间不累计。
- 手动选曲、自然结束、同曲循环、队列自动前进及 Automix 主声道交接结算上一轮。
  未出声的预播和交接后的尾声不计入；仅编辑队列或重新解析失效地址不伪造新一轮。
- 网易云账号变化、更换服务器、退出及关闭开关立即取消在途请求、丢弃未结算时长。
  旧结果不能写入新状态。已经被远端接收的请求无法通过本地取消撤回；超时不重试，避免重复记录。
- 登录错误关闭计量，等待账号恢复；普通上报错误不打断音乐。QQ 登录错误不会关闭网易云打卡。
  网络恢复／回前台可重新探测此前网络失败的支持状态；认证失败须重新登录或修正连接。

## 网关与凭据

新增受认证的 `POST /mobile/report`，输入为明确的网易云在线目录身份、曲目名称／歌手、计量秒数、音质及会话。
身份校验与客户端共用；云盘、本地、其他平台、非安全整数 ID、未满 30 秒或不合理时长被拒绝。
复用上一阶段抽出的原 provider 参数和响应判断，不伪造歌单来源，不在 Swift 复制网易云协议。

网关仅将校验后的原参数发往内部 `/scrobble/v1`，不会转发网关认证头；通用 `/mobile/request` 不开放这条写接口。
客户端断连会取消上游请求。响应必须有原协议明确的成功码，缺失、认证错误、HTTP 错误均不冒充成功。
Cookie 只从 Keychain 读取并送往配置的 HTTPS 网关，匿名 Cookie 不可用于打卡；无凭据或请求正文日志。

`/mobile/health` 增加可选的 `playbackReportProviders`。旧服务器未声明时不启用；后台原生层自行探测，
不依赖 WebView 提供能力列表。源码已具备接口，**现有线上网关未在本批部署**。

## 设置与兼容

播放器「更多播放选项 → 听歌打卡」复用原文案、store 与 `handleToggleNeteaseScrobble` action。
设置随原生 `folia.audio` 文档保存，旧文档默认关闭；恢复以原生值为准，不把旧 localStorage 值反写回来。
账号或网关不就绪时不能开启，已开启时仍可关闭；设置保存失败恢复上次确认值。
原桌面命令仍在原 command palette 中。播放器全屏布局、动画、主题和音频处理算法保持原行为。
