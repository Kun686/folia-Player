# 每日与历史推荐移植

## 功能与复用

网易云曲库新增「每日推荐」，复用原 `CollectionMutationController` 的日期切换、整表替换、
不喜欢换歌与每日限额规则，以及原 `OnlineCollectionResource` 的加载、取消和歌曲身份。
可查看今天／历史日期、显式刷新今日推荐、确认后提交不喜欢、播放或加入原生队列。
历史推荐不提供不喜欢操作；历史权限失败不妨碍已成功加载的今日歌曲。
推荐歌曲复用现有收藏、加入歌单及专辑／歌手菜单；进入目录时关闭推荐面板，避免残留的模态层遮挡播放器。

只补移动端触摸入口、会话保护及网关能力，没有新依赖。播放和队列仍使用既有原生桥，
未修改全屏播放器、歌词动画、音效或 Automix。日期选择器的高度为 44 CSS px；局部样式不影响其他面板。

移动端通过新增的 provider-explicit Omni 方法读取推荐，避免依赖桌面 active-provider store。
UI、移动服务均不直接访问具体 provider 或原始平台响应。原桌面 active-provider 方法保留。

## 正确性与会话

- 复用网易云 transport 已归一化的歌曲与日期，修复 provider 重新选择原始 `data.dates`／`data.songs`
  导致日期对象或未归一化歌曲覆盖正确结果的问题。业务失败／缺失列表明确报错，有效空数组仍可显示空结果。
- 不喜欢必须确认成功且得到有效歌曲，才交给原控制器替换对应条目；432 保留为原每日限额。
  日期切换失败保留原歌曲与日期。写入结果不确定时，要求重新读取，不自动重发。
- 账号与 Keychain 会话代次在异步边界检查。关闭面板后旧读取／旧替换不能提交；
  已送出的刷新或不喜欢请求不声称撤销，重新打开会等该请求结束再读取。
- 同一面板的日期切换和不喜欢串行处理，避免在历史列表上误换歌。不存在于当前列表的歌曲不发变更请求。
  失败经固定错误文本交给原控制器，不记录原始响应、Cookie 或网关凭据。
- 推荐变化只作用于推荐列表。用户已建立的播放队列沿用原歌曲身份，不自动替换正在播放的歌曲。

## 网关、部署与回退

health 增加可选 `dailyProviders`，只公布已启用的网易云；旧网关缺失字段则禁用入口并说明需要更新服务。
未登录时禁用个人推荐入口。QQ 不开放此入口或新推荐路由。

新增 GET 白名单 `/recommend/songs`、`/recommend/songs/dislike`、`/history/recommend/songs`、
`/history/recommend/songs/detail`。`afresh` 必须显式 true/false，不喜欢 id 必须为正整数，
历史日期必须是有效的 YYYY-MM-DD。沿用认证、固定内部后端、禁止 POST body／代理参数／重定向，认证头不转发。

部署固定的 API 4.40.1 对应四个模块已从该版本发布包核对，与本机 4.41.1 中这四个文件完全一致；
路径和 SHA-256 保存在 `upstream-source.json`。该核对证明路由与参数，不证明真实账号权限或平台可用性。
本轮没有操作真实推荐接口、安装依赖、部署网关或更新个人 mobile.28。

将来部署先更新固定网关版本并核验认证和能力，再安装匹配 App 验证真实推荐。
回退本批网关与 Web 资源即可，无存储迁移；版本回退不会撤销用户已提交的平台喜好。
私人 FM 的持续补曲／模式切换不在本批实现，仍需按原版行为继续移植；不能把静态推荐队列当作 FM。
