# 在线歌单曲目编辑移植

## 范围与复用

继续用户指定的不依赖真机工作。新增网易云歌曲「加入在线歌单」和自有歌单「编辑歌单歌曲」入口，
复用原 Omni、歌单权限规则、分页资源和 CollectionMutationController。QQ 沿用原 provider 的只读能力。
未新增依赖；全屏播放器、背景、歌词动画及音效实现没有改动。

- 歌曲菜单和专辑／歌手目录中的歌曲均可打开原平台歌单选择器；只展示当前账号可编辑的歌单。
  每页 100 个歌单，支持继续加载及对已加载歌单搜索；不会把 QQ 歌曲加入网易云歌单。
- 从当前个人歌单打开管理页，沿用原虚拟列表、播放／加入队列操作；移除前确认。
  不新增歌单创建、改名或删除接口。
- 添加直接通过 `omni.updateCollectionTracks`，避免 `addSongToPlaylist` 的桌面账号 store 刷新路径。
  复用原 tracks/detail 缓存键失效，刷新移动端当前选中的同一歌单，不覆盖后续搜索或其他平台页面。
- 移除由原集合控制器提交，确认成功才移除行；保留原「我喜欢」集合通过 `omni.likeSong` 取消收藏的分支。
  管理页首次读当前服务端数据；移除会改变分页 offset，故提交前暂停旧分页、成功后从首页重新读取。
  晚到的旧分页不提交，避免大歌单漏掉位于页边界的歌曲。

## 写入与会话边界

写入前核对原权限、当前登录账号及原生会话代次；账号改变或退出后，旧结果不能刷新旧列表。
同平台编辑串行执行。已发送请求可在关闭弹窗后结束，新弹窗等它结束再读账号／歌单；
关闭弹窗不声称撤销服务端操作。响应不确定时保留内容，明确提示重新读取后再操作。
客户端不自动重试写入；固定网易云 API 自身原有的 512 重试行为保持不变。

网易云 adapter 不再把 HTTP 成功当成业务成功：同时支持直接 `code` 和 `body.code` 包装，
业务码必须确认 200；包装层明确报错时也失败，301／401／403 标记登录失效。
歌单读取的业务失败／缺失列表同样明确失败，有效空数组仍可正常显示空歌单。
提交错误先转成固定错误，再交给原集合控制器记录，不记录上游响应正文、Cookie 或访问凭据。
服务端成功后的缓存清理失败单独告警，不把成功提交改成可重试的失败。

部署配置固定 `@neteasecloudmusicapienhanced/api` 4.40.1。本机安装为 4.41.1，
本轮另从固定 4.40.1 发布包读取 `module/playlist_tracks.js`，与本机该文件的 SHA-256 相同：
`882688ccb3053cf93910d1ab8d80ebacb7e89309145191fcee747b4b12714a8c`。
这是响应包装的源码核验，不是实际账户写入验收；没有安装或更新这项依赖。

## 网关与回退

`/mobile/health` 增加可选 `playlistEditProviders`，仅对已启用的网易云返回能力。
旧网关缺少字段时，添加入口禁用并说明需要更新音乐服务；管理入口不开放。

新增网易云 GET `/playlist/tracks`：只允许 `op=add|del`、正整数 `pid` 和 1–100 个正整数曲目 ID。
沿用访问认证、固定内部后端、禁止 POST body／任意代理参数／重定向，网关认证头不转发。
QQ 不开放任何新写接口；实际平台权限仍由上游认证校验。

将来部署须按既有移动网关流程更新固定源码／镜像，并验证认证与 health 能力后再测新 App。
可回退本批前的网关与移动资源；没有新增凭据或曲库迁移。已由用户提交的远端歌单编辑不会因版本回退自动撤销。
本轮没有更新服务器，也没有构建或安装个人 IPA，个人安装记录仍为 mobile.28。
